**Eidos is a Go CLI that turns OpenAPI specifications into complete Terraform
provider code** built on the Terraform Plugin Framework. Point it at an OpenAPI
2.0 / 3.0.x / 3.1.x spec and it parses, normalizes, and transforms the spec into
an intermediate representation, then emits a ready-to-extend Terraform provider
— resources, data sources, actions, ephemeral resources, list resources,
functions, documentation, tests, and release tooling — with deterministic,
byte-identical output for the same input.

## What it supports

**Spec versions & auto-detection.** Eidos ingests all three OpenAPI generations
and detects the version automatically — no flags needed:

- **OpenAPI 2.0 (Swagger)** — `swagger: "2.0"`
- **OpenAPI 3.0.x** — `openapi: 3.0.x`
- **OpenAPI 3.1.x** — `openapi: 3.1.x`

Ambiguous or unsupported constructs are never dropped silently: the parser
emits typed `diagnostics` (errors/warnings/info) with source locations, and the
validator rejects specs that would produce invalid output.

**Static config definitions.** Generation behavior is controlled declaratively
by a `generator.yaml` build config, scaffolded with `eidos generate-config`:

- provider name, namespace, module path, and protocol version
- `resource_overrides`, `datasource_overrides`, `action_overrides`,
  `ephemeral_resource_overrides`, `list_resource_overrides`, and
  `function_overrides` — promote an
  inference-classified operation, rename a construct, wire explicit
  create/read/update/delete operations, mark write-only or sensitive
  attributes, and more
- global CRUD timeouts, auth credentials, logging, and Terraform test generation

Without a config file, Eidos auto-infers resources, data sources, actions,
ephemeral resources, list resources, and functions straight from the spec.

## What it generates

For a given spec, Eidos emits a complete provider module:

- **Terraform Plugin Framework code** — managed resources, data sources,
  actions, ephemeral resources, list resources, and provider-defined functions,
  with schema attributes derived from the spec
- **A typed HTTP client** — resources with a complete create/read/delete mapping
  are **wired** to real API calls via a generated client (path-parameter
  substitution, auth interceptors, pagination, retries, logging); constructs not
  yet wired emit honest runtime diagnostics instead of `TODO` stubs
- **Documentation** — Markdown docs per construct, examples, and a provider README
- **Tests** — unit, acceptance (`TF_ACC=1`), and Terraform `test` files with a
  deterministic mock server
- **Release tooling** — `go.mod`, `.goreleaser.yml`, and a GitHub Actions
  release workflow
- **Validation preview** — `eidos generate --dry-run` prints the full planned
  file list before writing anything

## Quick start

```bash
# Install via Homebrew (recommended)
brew tap signalbreak-labs/tap
brew install eidos

# Or install with Go (latest, or pin a release: @v0.3.0)
go install github.com/signalbreak-labs/eidos/cmd/eidos@latest

# Generate a starter build config
eidos generate-config --spec ./mycloud.yaml --provider-name mycloud --output mycloud-generator.yaml

# Dry-run: preview the files that would be generated
eidos generate --spec ./mycloud.yaml --config ./mycloud-generator.yaml --dry-run

# Write the provider to disk
eidos generate --spec ./mycloud.yaml --config ./mycloud-generator.yaml --output ./terraform-provider-mycloud
```

## Also included

- **`eidos api`** — an HTTP validation server (`POST /api/v1/validate`) that
  returns diagnostics plus an IR preview for a spec.
- **`eidos mcp`** — a Model Context Protocol server exposing
  `generate-config`, `inspect`, `generate`, `validate-schemas`,
  `override-preview`, `lookup`, and `suggest-resources` tools.
- **Shell completion** — `eidos completion bash|zsh|fish|powershell` (Cobra).
- **Remote specs** — `--spec` accepts an `https://` URL with an SSRF guard,
  size/timeout caps, and optional env-var auth.
- **Polymorphism & advanced shapes** — `oneOf`/`anyOf` unions, `allOf`
  flattening, circular references, webhooks, callbacks, OAuth2/API-key/basic/
  bearer/OpenID Connect auth, form/multipart/XML request bodies.

## Development

Toolchain, lint, formatting, and testing conventions live in
[`docs/standards.md`](docs/standards.md). The project uses Go 1.26.0 with
`toolchain go1.26.6` (CI reads the version from `go.mod`), golangci-lint v2
pinned to Go 1.26, and `goimports` with local prefix
`github.com/signalbreak-labs/eidos`. Releases are versioned with release-please and
shipped as cross-compiled GitHub Release binaries by GoReleaser, which also
publishes the Homebrew cask to `signalbreak-labs/tap`; `v*` tags follow
Semantic Versioning.
